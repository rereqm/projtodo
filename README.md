# Портал командировок и расходов (MVP)

## Назначение приложения
Веб-приложение для сотрудников компании, позволяющее планировать командировки и вести учёт командировочных расходов. Включает в себя управление поездками и фиксацию затрат (билеты, отели и т.д.).

## Реализованные экраны (Лабораторная №1)
1. **Экран «Расходы»** — список всех расходов. Отображает название траты, сумму, статус утверждения бухгалтером и дату.
2. **Экран «Командировки»** — список поездок в виде сетки карточек. Отображает направление, цель поездки и выделенный бюджет.
3. **Общий каркас (Layout)** — верхняя панель навигации для переключения между экранами.

*(В планах на следующие лабораторные: интеграция с бэкендом, авторизация, а также модуль OCR для автоматического распознавания чеков).*

## Технологический стек
*   **Frontend:** React, TypeScript, Vite, React Router, Mantine UI.
*   **Структура:** Feature-Sliced Design (упрощенная).

## 🐍 Backend (FastAPI + PostgreSQL)

Серверная часть проекта реализована на Python с использованием фреймворка FastAPI. В качестве базы данных используется PostgreSQL, для взаимодействия с ней — ORM SQLAlchemy. Валидация входящих и исходящих данных обеспечивается библиотекой Pydantic.

### 📊 Модель данных
В проекте реализованы две связанные сущности (связь «Один-ко-Многим»):
1. **Trip (Командировка)**:
   * `id` — первичный ключ (автоинкремент).
   * `title` — название/направление командировки.
   * `description` — цель поездки (необязательное поле).
   * `budget` — выделенный бюджет (тип Numeric).
2. **Expense (Расход)**:
   * `id` — первичный ключ.
   * `title` — на что потрачены средства.
   * `amount` — сумма расхода.
   * `is_approved` — статус утверждения бухгалтерией (по умолчанию `False`).
   * `created_at` — дата и время создания записи (устанавливается сервером БД автоматически).
   * `trip_id` — **внешний ключ (ForeignKey)**, связывающий расход с конкретной командировкой. При удалении командировки её расходы удаляются каскадно.

### ⚙️ Настройка окружения (Environment)
Параметры подключения к базе данных вынесены в переменные окружения. 
В папке `backend/` находится файл `.env.example` с шаблоном настроек. Для запуска проекта необходимо создать рядом файл `.env` и заполнить его своими данными (файл `.env` добавлен в `.gitignore` и не попадает в репозиторий).

Пример содержимого `.env`:
```env
POSTGRES_USER=todo_user
POSTGRES_PASSWORD=todo_password
POSTGRES_SERVER=localhost
POSTGRES_PORT=5432
POSTGRES_DB=todo_db
